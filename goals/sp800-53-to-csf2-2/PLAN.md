# sp800-53-to-csf2-2

0. Definitions this plan uses, so no item leans on the paper by section number; every line below is a criterion the build's tests and reviewers read against
    - The paper is `models-propose-rules-decide_1.1.md` in MoxyWolfLLC/Projects at commit 4c3a05ec6, under CKI/11 - Project Knowledge/Papers/models-propose-rules-decide/; the reference runner 1.1.0 is `runners/models-propose-rules-decide/` in this repository at commit eb0aeb2 (Zenodo 10.5281/zenodo.24295089)
    - Levels are the four set-theory types `subset_of`, `intersects_with`, `equal`, `superset_of`; the null is `no_relationship`
    - Per-stage identities (the paper's Section 3): extraction = unit release and attempt number; retrieval = unit release, extraction output id, retriever and index versions, hub revision, route parameters; proposal = unit release, extraction output id, candidate hub entry and revision; vote = the proposal's evidence, the quoted spans shown and the vote-stage parameters, the confidence threshold among them; ruling = route, reason code and the exact packet shown by stored output ids
    - Domain parameters (the paper's Table 5): unit, hub, answer scale, scope rules, route, question templates, evidence tests
    - The measures (the paper's Table 6): precision of automatic writes per level with a one-sided 95% Wilson lower bound; precision of voted no-relationship with the same bound; missed links with the non-retrieved stratum weighted by its inverse inclusion probability; single-source error rates; coverage; council agreement (Krippendorff's alpha on the double-ruled subset); reuse cost; review queue size and age
    - E1 is the evidence card "needs a new hub entry"; with a fixed hub it is present and never fires, and `check.py --table` reports its row as `present_unreachable`, which counts as PASS; every other card id must be reached on fixtures
    - The two undos: publication reversal (reactivate the previous set; pass when public reads equal a fresh replay of it) and data recovery (restore a bad write's footprint rows; pass when exactly those rows return to their pre-write values and no other row changes)
    - Model calls are every request to a provider, embeddings included, and every one is counted against the $60 cap; the $10 reserve sits inside the $60, and the guard's remaining allowance is $60 minus spend minus the reserve until item 9's deliverables start, when the reserve is released: the guard reads a `phase` field the runner sets to `deliverables` when item 9's deliverables start, and only calls made in that phase may draw on the reserve
    - Only Mistral is reached through OpenRouter; OpenAI, Anthropic and Google are called directly. k, the retrieval cut-off, is fixed at 8 in `protocol.json` and is not tuned; the missed-link sample is drawn outside the retrieved top-8
    - Token ceilings are hard caps the adapter enforces per call; calibration tunes prompt wording and the confidence threshold inside them, never past them, and is capped at 6 revisions
    - Frozen call counts bind the budget; the calibration cap is part of them
    - The run's ruling stage is rule-based (cards H1 to H4 over stored votes) and costs no model call; a council ruling is a gold ruling by the three council voices, each reached through its own provider with the same evidence classes as any call. A family is a base control and its enhancements, for the split constraint and for the per-level dependence count alike; the 18 control families of the catalog are a stratum label only
    - Assisted-review packets (which show the run's outputs) are never primary gold; the primary gold audit covers primary packets only
    - Gold for the sealed-test split is assembled in item 8, after its predictions are stored, under the same frozen policy as item 7
    - "Insufficient evidence" is a recorded gate decision, `closed_insufficient`, with its n
    - Noun substitutions are not deviations in the graph diff; the allowed normalizations are listed in the baseline file

1. Sources pinned: `fetch_sources.py` fetches SP 800-53 Rev. 5 (OSCAL JSON from usnistgov/oscal-content), the CSF 2.0 core (CPRT JSON export) and the CSF 2.0 informative-references workbook; writes `sources.json` with URL, retrieval date, bytes and SHA-256 per file; counts active base controls, enhancements and withdrawn controls from the pinned catalog and functions, categories and subcategories from the export; tags every reference entry in `reference_semantics.json`
    - a first run writes `data/`, `sources.json` and `reference_semantics.json`, prints each file's name, bytes and SHA-256 and the counts to stdout, and exits 0; `--check` re-hashes `data/` against `sources.json` without changing it and exits 0 on a match or 2 with both hashes on stderr; a first run that finds an existing `sources.json` whose hashes differ exits 2 and changes nothing
    - every count in `sources.json` is computed from the files, never typed in
    - every entry in `reference_semantics.json` carries `five_class` or `association` with the source field that justifies it; `absent` is a summary-level policy statement only, never on an entry, since an entry is by definition a link that exists
2. Protocol frozen: `freeze.py` writes `protocol.json` holding the exact sample size within 300 to 400, strata by control family and base-versus-enhancement with selection probabilities, the family-preserving three-way split (a base control and its enhancements always share a split), the adjudication policy and rubric text, the missed-link estimand (share of ruled true links the run recorded as no-relationship or never retrieved, over ruled true links, non-retrieved stratum weighted by the inverse inclusion probability, the unit's non-retrieved pool size over r, with r the same per-unit draw count for every unit) with r and inclusion probabilities, the anchoring comparison (matched pairs, blind versus assisted council sessions, the statistic compared), the 20% double-ruled draw, r3's change as a formula only: the confidence threshold that calibration later freezes in `config.frozen.json` minus 0.2, floored at 0 (if the floor leaves the value unchanged the offset is +0.2 instead, capped at 1); the numeric value is recorded in `config.frozen.json` after calibration, never in `protocol.json`; r3 applies to the sealed-test split only: its vote identities change, so exactly that split's vote calls are re-asked (the r3 allowance in the budget, worst case every one of them); rulings whose packet names a re-asked vote are re-derived from the new stored output ids at no model cost and are counted separately as re-derived rulings, not re-asked calls; evaluation-split decisions keep the identities they were stored under (r1, every gate closed, so the pass yields proposals and votes and no automatic write; per-level n counts proposals the council ruled), and replay runs every decision under the revision it was stored under, and the budget calculation (model ids, per-call token ceilings, unit prices, call counts per stage: extraction and per-unit query embeddings one per sampled unit, proposal and vote counts derived from the sample and k = 8, hub embeddings fixed at the active subcategory count, calibration at its six-revision cap, voters fixed at three, council calls three voices per packet over every packet class the plan rules (primary proposals, the voted-no-relationship census, the missed-link draw, the SS audit samples, the matched assisted pairs, the sealed-test split's own set of each) plus the double-ruled 20% of primary packets, the r3 allowance, total, the reserve of exactly $10 inside it); `protocol.sha256` is written before any model call
    - `python3 -I freeze.py` prints the hash to stdout and exits 0; exits 3 with a stderr line naming the family if any family's units land in more than one split
    - the budget calculation totals under $60 with a stated reserve of exactly $10 for validation and reporting, and every per-unit count in it is derived from `protocol.json`'s own sample and k while each fixed count names its source
3. Provider adapter and budget guard: `providers.py` calls OpenAI (extraction, proposer and embeddings), Anthropic, Google and Mistral via OpenRouter (the three voters), and the council (three model voices through /council:deliberate, counted in the budget like any other call) with versioned prompt templates for extraction, proposal and vote; every call records the per-stage question and evidence identities, token usage, and provider-reported cost where the response carries it; the guard refuses a call whose maximum expected charge (token ceiling times unit price) exceeds the remaining allowance
    - a refused call prints `refused: budget <remaining>` to stderr, appends an accounting row with `refused: true`, returns no output, and the calling pass exits 4
    - `accounting.jsonl` rows carry `evidence: provider_reported | usage_priced | unpriced | refused` and the provider, model and stage; a `refused` row records zero cost and charges nothing; an `unpriced` row is charged at its token ceiling times unit price against the cap and the remaining allowance
    - `python3 -I -m unittest tests_adapter.py` runs the adapter against a recording stub with no network and exits 0
4. Retriever and store: `retrieve.py` builds embeddings over the active subcategories counted in `sources.json` (expected 106; the script exits 7 if the count differs) with OpenAI `text-embedding-3-small`, writes `index.json` with model id, dimension, hash and k = 8 from `protocol.json`; `store.py` creates the SQLite schema with the per-stage identities; `--replay` disables every outbound call and counts attempts
    - `index.json` is written after `protocol.sha256` exists and its embedding calls appear in `accounting.jsonl`
    - any outbound attempt in replay mode raises, is counted in the replay report, and the runner exits 5
5. Domain parameters and cards: `cards.py` copies the seven card lists of runner 1.1.0 unchanged (intake I1, I3, I4, SS-scope, I5; audit A1, A2; retrieval SS-retrieval, R2; evidence E1 to E4; curator K1 to K3; triad T1 to T5 with quorum from the panel size; ruling H1 to H4) and supplies the domain predicates through structured outputs; `set_r1.json` lists every gate closed, the engine hash, and the seven domain parameters: unit (an active SP 800-53 control or enhancement), hub (the active CSF 2.0 subcategories from `sources.json`, 106 expected, at hub revision 1), scale (the four levels plus the null), scope rules (withdrawn controls out by metadata; a control with no statement text out by content under SS-scope), route (retrieval only), question templates (versioned ids), evidence tests (quotes verbatim in the control text; a level and quotes that disagree is a conflict)
    - `python3 -I check.py --table` reports every card id reached on fixtures, with E1 as `present_unreachable`, and exits 0 only when every row is PASS or `present_unreachable`; any FAIL row exits 1
    - `set_r1.json` names every gate as closed and `cards.py`'s card ids equal runner 1.1.0's, checked by a test
6. Calibration pass: `run.py calibrate` runs the calibration split, scores each revision against the pinned NIST informative references for that split as weak labels (link versus no link only, since the references carry no level; the threshold is tuned on that binary agreement and levels are not scored before item 7, and no council ruling is used before item 7), tunes prompt wording and the confidence threshold within the frozen token ceilings and the six-revision cap, records every revision in `calibration.jsonl` with its cost, and writes `config.frozen.json` with its hash
    - stdout prints per-revision cost and the chosen configuration; exit 0; exit 4 on a budget refusal
    - no evaluation or sealed-test unit id appears in `calibration.jsonl`, checked by a test
7. Evaluation pass and gold: `run.py evaluate` stores predictions for the evaluation split; `gold.py` assembles the reference standard under the frozen policy (NIST references kept as associations, and a `five_class` entry, if any, carries its level into gold, though the pinned sources yield none; blind primary council packets with source text, context, candidate and rubric only; the 20% double-ruled draw; the matched blind-versus-assisted pairs in separate sessions); `audit.py` draws up to 30 outputs per card, pooled across the evaluation-split units only, from SS-scope and SS-retrieval, all of them when fewer exist, recording the pool size, the council rules them, and the error rate per card goes into `score.json`; council agreement is Krippendorff's alpha over the 20% double-ruled draw, written to `score.json`; the missed-link draw of r non-retrieved candidates per unit is ruled by the council in the same pass and feeds the HT estimate; `score.py` reports per level and for `no_relationship` and qualifies gates (open when n is at least 25 and the Wilson lower bound is at least 0.90; `closed_insufficient` when n is under 25; `closed` otherwise); coverage is the share of evaluation-split units with at least one proposal ruled a true link, read from the store, and that is the one coverage RESULT.md reports; retrieved candidates the run voted no-relationship are all ruled by the council in the same pass, weight 1, and a true link among them counts as missed alongside the weighted non-retrieved draw; `set_r2.json` is written and hashed
    - `gold.py audit` exits 0 only when no primary packet contains a proposal, vote, confidence, route or prediction
    - `score.json` reports one row per level and one for `no_relationship`: n, correct, Wilson lower bound, gate decision (`open`, `closed`, `closed_insufficient` with n), and the count of families contributing more than one outcome at that row; plus the SS-scope and SS-retrieval error rates with their n
8. Sealed-test pass, policy change, replay and undos: `run.py test` stores predictions under r2 before any ruling for that split is read; `gold.py --split test` then assembles the split's gold under the same frozen policy and `audit.py --split test` runs the same SS audit for that split only after its predictions are stored; `score.py --split test` scores the split's automatic writes per level under r2, which is where precision of automatic writes comes from (a level with no automatic write reports n = 0 and `closed_insufficient`, never `not produced`); the sealed-test SS audit's error rates go into `score.test.json` and RESULT.md reports both splits' rates; `queue.py` writes `queue.json` with review queue size and age from the store; `run.py policy r3` applies the predeclared delta, derives expected invalidations from the stage identities before any call, compares to observed, and reports dollars; `run.py replay` replays every live decision with outbound calls disabled; `undo.py` runs publication reversal (reactivate r1 after r2, on a copy of the store taken after r2 and before r3) and data recovery (a bad write that corrupts exactly five decision rows, whose footprint is exactly those five rows, then restored) in copies of the store
    - `policy_report.json` lists expected and observed re-asked calls per stage and re-derived rulings, whether each pair is equal, and their cost in USD from the adapter's per-call records (the reuse cost RESULT.md reports)
    - `undo_report.json` shows complete public reads equal after reactivation, and the five footprint rows restored with zero untargeted rows changed
9. Graph conformance and deliverables: `graphs/run.mmd` and `graphs/policy.mmd` redrawn with the domain's nouns as labels only; `conform.py` diffs nodes, edges, card ids, lanes, stores and decision semantics against `baseline/appendix_c.md`, a copy of the paper's Appendix C at commit 4c3a05ec6 with its hash pinned in `baseline/appendix_c.sha256` and the allowed noun normalizations listed beside it
    - `python3 -I conform.py` prints zero deviations or one line per deviation to stdout and exits 0 either way; exits 6 if the baseline's hash doesn't match the pinned one
    - the output names E1 as present and unexercised
    - deliverables: `RESULT.md` with every measure named in this plan's definitions (reuse cost from item 8's policy report; single-source error rates from the SS-scope and SS-retrieval audit samples of item 7 and item 8, reported per split; review queue size and age from the store at the end of item 8; a measure with no producing item is reported as `not produced` with the reason), the HT missed-link estimate with weights and uncertainty, the anchoring comparison, the conformance result, the policy-change and undo reports, and accounting totals by evidence class; `README.md` with the runner's open choices; `expected/check_output.txt`; a publication package under `package/` left unpublished
    - `python3 -I check.py --table` prints the same table as item 5, extended with one row per Scenario in the Scenarios section of this goal's `GOAL.md` run on fixtures, and exits 0 only when every row is PASS or `present_unreachable`, else 1
    - every number in `RESULT.md` names the file it comes from, and missing cost evidence is listed by provider
